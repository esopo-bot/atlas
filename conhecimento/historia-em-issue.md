# História em issue

Todo trabalho ganha um endereço antes de começar: **uma história, uma
issue**. O que se executa — template, regras de abertura, sequência da
sessão, evidência — está na skill `trabalho-por-issue`. Um fato, um lugar.

## O desenho

| Peça                      | Vira                      | Fecha quando               |
| ------------------------- | ------------------------- | -------------------------- |
| História — o que se quer  | issue                     | os critérios dela passaram |
| Tarefa — um passo         | critério dentro da issue  | o instrumento provou       |
| Lição — o que se aprendeu | página em `conhecimento/` | não fecha — fica           |

## A fila e o nome

- Onde a issue nasce, o padrão de nome e a fila são configuração do
  repositório: `nucleo/configuracao.json`. Sem o arquivo preenchido,
  pergunte ao dono — nunca decida de cabeça.
- O fluxo da fila é de cada repositório e se escreve lá: o que acontece com
  achado no meio do trabalho, e o que vira pergunta ao dono antes de entrar.
  A camada não opina — ela só garante que a resposta esteja escrita.

## As leis do corpo

- **Critério dentro da issue; pedaço de outra pessoa vira outra issue,
  ligada por link — nunca sub-issue.** Issue-mãe e filha envelhecem uma
  contra a outra.
- **O corpo é o estado; o comentário é o evento.** O corpo se reescreve e
  diz o que é verdade agora; o comentário fica e diz o que aconteceu.
- **O chamado vira issue e fecha; a lição é conhecimento e fica.** O teste:
  se o mesmo texto servir daqui a seis meses, é conhecimento — vai para
  `conhecimento/`; se só fizer sentido neste trabalho, morre com a issue.
